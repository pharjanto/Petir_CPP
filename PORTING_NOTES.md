# Faithfulness and compatibility notes

This is a source-level port of the active Petir 1 engine, not a new chess engine. The search and evaluation were translated unit by unit. The separate engine interface replaces VCL forms, Windows timer events, and Delphi threads. The original GUI and inactive experimental evaluation/move-generation variants are retained in the original uploaded archive, but are not part of the C++ engine build.

## Semantics retained

- `Integer`/`Longint` remain 32-bit, `Byte` 8-bit, `Word` 16-bit, `Shortint` signed 8-bit, and `Smallint` signed 16-bit, on a 64-bit process.
- Int64 bitboards and keys use unsigned 64-bit storage to preserve bit patterns, modular multiplication, and logical right shifts without signed overflow. No pointer is narrowed to an integer.
- The original arbitrary array bounds, including negative piece indices and 1-based move lists, are retained by `pas::Array`. Strings use Pascal's 1-based indexing.
- Delphi overflow-check-disabled integer arithmetic is represented by explicit modular helpers. GCC/Clang builds also disable strict aliasing because the original bit-scan/popcount routines inspect 64-bit values through 16-bit pointers.
- Boolean expressions retain the original short-circuit behavior and Pascal operator precedence. Records and positions retain value-copy semantics except for the read-only evaluator, which takes a const reference to avoid copying the position on every call. Its draw, SEE, and bishop-attack helpers also accept const positions.
- The fractional-ply scale, main-search extensions, aspiration windows, null move, futility conditions, SEE, killers/history, root move order, and full classical evaluator retain the original algorithms. The C++ build always uses the 4.39 history-based quiet-move reduction conditions and omits the positional quiescence restart; these changes are listed below.
- The material and piece-square values, including asymmetries between colors, are retained. No tuning, bitboard redesign, pruning consolidation, or new search heuristics were applied. Correctness changes are listed below.
- Delphi unit visibility is preserved when binding symbols: implementation-private piece values in `movgen` and `usee` do not shadow `header`'s centipawn values in callers. The initial translator violated this rule, causing mate scores around -99 instead of -20000 and incorrect capture/threat scaling. Search, root, and tools bindings and the translator lookup have been corrected.
- Packed book records remain 10 bytes (`uint64 key`, `uint16 weight`). The TT record remains packed, 16 bytes, with the original 16-bit move field.
- Hash initialization reproduces Delphi's LCG, seed 99999, unused-square RNG consumption, and **right-to-left** evaluation of the three Random calls in each key expression. The starting hash is `3423812783342919194`, matching the original source's book comment and supplied book keys. Opening move selection remains weighted and randomized after hash initialization.
- `lastbitp` retains its unusual original behavior: it selects the highest occupied 16-bit block and takes that block's *least* set bit. The empty-board result remains -1. MSVC x64 uses baseline BSF/BSR intrinsics to avoid per-call CPU-feature dispatch; other builds use C++20 `std::countl_zero` and `std::countr_zero`. Tests compare every nonzero word in each block with the legacy lookup, including lower occupied blocks.
- `firstbitp` uses baseline BSF on MSVC x64 and C++20 `std::countr_zero` elsewhere. It preserves the least-set-bit index and the original zero result for an empty board; the self-test compares all 65,535 nonzero word values in each of the four blocks.
- Evaluation bit counts replace the per-bit loop and four 16-bit mobility lookups. MSVC x64 detects POPCNT support once and selects a specialized evaluator once per call, avoiding CPU checks at each count; its fallback retains table counting. Other builds use C++20 `std::popcount`. Pointer counts load the same eight bytes with `memcpy`, without alignment or aliasing assumptions. Tests compare counts and single-bit predicates against the legacy loop over every 16-bit word in each block, mixed boards, empty/full boards, and bit 63.
- Evaluation uses least-bit iteration for both colors' rooks, knights, bishops, and queens: their scores are integer sums and attack-mask unions, so their order does not affect the result. Passed pawns are found for the whole board at once with file fills, which equals the per-pawn `whitePassedPawnMask`/`blackPassedPawnMask` test (the self-test checks the masks square by square); only the foremost passer of each file is scored, as before. Shared legacy scans and SEE selection order are unchanged.
- Pawn file flags use three shifts/ORs. Doubled-pawn counts equal the number of pawns minus the number of occupied files; isolated files have no occupied neighbor. Bad-bishop counts use square-color and rank bitboards. These replace repeated per-pawn tests while retaining the existing weights and rank restrictions. The terms that depend on the two pawn bitboards alone (pawn square values in total and per wing, isolated-pawn penalties and count, doubled count, foremost passers, connected-passer bonus) are cached in a 4096-entry pawn table keyed and verified by both pawn bitboards, so a cached entry always equals a fresh computation; terms that read the board array, kings or pieces are computed every time. Endgame rook/knight activity builds each side's attack map once per evaluation instead of once per piece. Regression positions freeze full and lazy scores for promoted pieces across multiple 16-bit blocks and mixed pawn files, for both sides and both `infhr` modes.
- The translation uses the original build definitions `INDEBUGA`, `CEKMOVEa`, and `TESTING`, plus unit-local directives. The inactive `stat`, `calleval`, and `CEKMOVE` branches remain inactive.

## Explicit compatibility changes

| Change | Reason / effect |
|---|---|
| Exact KPK evaluation | Positions with exactly two kings and one pawn bypass the classical evaluator using a table generated once at startup (192 KiB persistent storage, no external files). The table solves win/draw and distance to the next winning pawn move, including double pushes, captures, promotion stalemate, and rook underpromotion. It normalizes both pawn colors and file reflections, uses the actual side to move under `infhr`, preserves draw contempt, and applies the existing halfmove clock to the exact reset distance. Winning scores stay below queen value and reward progress; they are not mate-distance scores. All 165,676 legal normalized positions match independent Syzygy WDL and DTZ probes. Other material retains the classical evaluation. |
| Lazy evaluation stages 2 and 3 removed | Stage-1-only lazy evaluation is the default in all C++ builds. The first lazy checkpoint runs only when `draw2` is false and the halfmove counter is below 80, so it cannot bypass those final scaling terms. If it does not return, evaluation continues through all remaining piece, king, and scaling terms. The later 250-point and 170-point shortcuts and the unused `dynamiclazy2` helper have been removed from the C++ evaluator. |
| Positional quiescence restart removed | Quiescence no longer restarts normal search for a positional bonus. The build option has been removed. Check evasions, capture/check search, stalemate detection, and deadline checks remain active. |
| Unconditional 4.39 history-based quiet-move reduction conditions | All C++ builds use this reduction; the build option and comparison presets have been removed. `src/search.cpp` follows `G:\My Drive\Programku\chess\skakmaster3\4.39 SRC\search.pas:758` for this block: non-PV nodes at plies 2–6, from the 13th legal move, requiring `hist_tried >= Min_TRY` and `hist_succ <= hist_tried >> 6`, and checking advanced pawns for the moving side. The reduction remains one ply. Other reduction blocks, re-search rules, and later C++ fixes are retained. The positional quiescence restart has been removed independently of this reduction. The unmodified Pascal archive and translator still contain the Petir version of this block. |
| Initialize C++ local scalars and return values to zero | Delphi leaves some locals and some early-return values unassigned. Reproducing stack garbage would create C++ undefined behavior. This can change affected paths, notably checked-node quiescence locals; there is no defined Delphi value to preserve. |
| Stop quiescence at cancellation | Lets the console worker acknowledge `stop` and fixed-time deadlines. This affects interrupted searches; the adapter returns a legal fallback when no root move completed. |
| At depth 63, stop searching and return the existing evaluation | Prevents the original 64-ply arrays from being indexed outside their range. Quiescence detects terminal mate/stalemate before this fallback. |
| Optional Pascal array checks, disabled by default for performance | `PETIR_CHECK_BOUNDS=ON` detects an overflow rather than corrupting memory. With checks enabled, the console reports an error and returns a legal fallback if an original capacity is exceeded. |
| Move lists enlarged to 256 with an unconditional capacity check; black quiet moves use record indexing | Positions with promoted pieces can exceed the original 100 moves. Raw pointer writes bypassed Pascal bounds checks. The capacity check remains active in performance builds. |
| Material-scale and king-pressure evaluation indices saturate at the last table entry | Promotions can exceed the material tables' index 41; high king pressure can exceed index 63. Values within the original ranges are unchanged. |
| Bishop counts updated on promotion | Both promotion routines increment the corresponding bishop count so evaluation sees the new bishop and a later capture decrements a valid count. Regression tests cover first and second bishops, promotion by capture, and subsequent captures for both colors. |
| Main and quiescence search move lists are filled on demand rather than zeroed at entry | Generators assign both move and score for each counted entry before ordering reads it. Scalar initialization and unconditional move-list capacity guards are retained. Regression tests compare generator output from different initial byte patterns. |
| Standard-library worker and millisecond time manager | Replaces VCL threads and the 250 ms timer. One 64-bit monotonic command timestamp includes setup in the deadline. Main search, quiescence, root, aspiration, and MTD(f) poll the shared stop/deadline predicate. There is no sleeping ticker to join before publishing a move. Search remains single-threaded. |
| Separate soft/hard budgets and configurable response overhead | Both protocols use increments and move horizons, reserve 50 ms by default, bank future overhead, and have no 250 ms minimum. Score changes can adjust only the soft target; iteration-duration prediction and the hard ceiling bound extra search. Low clocks bypass search with a validated legal TT hint or the first legal root move. Late WinBoard clocks can tighten the hard ceiling. |
| Constant-time hash aging | A six-bit generation tag replaces the per-move full-table scan, preserving the 16-byte entries, key/counter validation, retained score probes, and depth-or-age replacement. The generation wraps every 64 searches; wrap can change replacement priority for a long-lived entry but cannot bypass score-validity checks. Explicit `Clear Hash` still clears the table. |
| Console UCI/WinBoard adapter | Replaces GUI actions. FEN input is validated and restores en passant and counters; legacy `readnotation` remains in the translated core. Protocol move input is checked using the original generators. |
| Depth-1 start, completed-iteration results, and explicit depth limits | Each new search begins at depth 1 and searches root moves at every depth. Root hash probes provide move-ordering hints; score cutoffs remain enabled below the root. Hash entries are retained and aged between moves, with the original history decay and killer reset. Game repetition history is preserved. Depth limits, including limits combined with clocks, are honored. An interrupted iteration cannot replace the last completed move, score, or PV. |
| Safe root castling history updates | Root quiet-move cutoffs read the moving piece from its source square before the move, using the shared history/killer updater. Castling codes 65 and 66 remain valid history indices and are never used as board-square indices there. This corrects an inherited Pascal defect. |
| Halfmove-aware transposition scores | The unused final byte of each 16-byte TT entry stores the halfmove counter. Main-search and PV probes require a matching counter for score reuse; mismatches can still supply a move-ordering hint. Root search uses the move hint without a score cutoff. Board keys remain unchanged for opening-book compatibility and repetition detection. |
| Legal en passant check evasions | Both evasion generators verify the captured pawn and empty destination, make a candidate on a copy, and reject any move leaving the king checked. This also admits legal en passant interpositions against sliding-piece checks. Quiescence decodes each move's destination even while in check, so its post-move en passant safety check runs. |
| Terminal stalemate detection in quiescence | Before stand pat, cached evaluations, or the depth-limit evaluation, quiescence checks whether any legal move exists. Quiet pawn pushes and king moves provide early exits; remaining captures and quiet moves receive full king-safety checks. Legality probes preserve the input position and do not inflate search node counts. |
| Faster nonchecked move-existence probes | Pawn pushes are filtered for empty destinations using bitboards before pin tests. King destinations use direct attack tests, which are sufficient because the current king is not checked; captures and other quiet moves keep the full make/check fallback. Terminal stalemate detection and search results are preserved. |
| Native scan-and-clear iteration in move generators | Least-bit loops clear with `bits &= bits - 1`. Legacy loops reverse the four 16-bit words once, then scan least bits and map squares back with XOR 48. Every converted loop retains its original move order and scores, including the mixed scan orders in the original generators. Global scan semantics and move-list capacity checks are retained. |
| Cached pinned-piece masks in nonchecked search nodes | Main search and quiescence calculate friendly pieces that are the sole blocker between their king and an aligned enemy slider. Only those pieces need the existing discovered-check probe for each candidate move. King attack checks, checked-node evasion generation, and post-move en passant checks are retained. Quiescence computes the mask after stand-pat cutoffs and empty-list exits. |
| Range-based first-maximum move selection | Checked first/last entries establish a valid contiguous range, avoiding repeated capacity checks for every score. A branch-free pass finds the maximum score, then a scan selects its first entry. The first maximum wins ties and is swapped into the current slot, preserving the original move sequence. The unconditional move-list capacity guard is retained as one compare per access, with its exception raised out of line. |
| Avoid clearing SEE's temporary exchange list | The forward pass writes every list entry subsequently used by the backward pass. Removing the initial clear preserves all signed 8-bit exchange values, attacker choices, xray behavior, and SEE scores. Frozen-score fixtures and differential tests cover both side conventions. |
| Cache-resident repetition table | Each side's table has 16,384 slots instead of 65,536 (320 KiB instead of 1.25 MiB in total). Lookups compare full 64-bit keys, and search inserts and deletes in stack order above the permanent game history, so the original open addressing without tombstones still finds every live entry. Counts are therefore independent of table size while a free slot remains; 16,384 slots exceed the positions of any legal game plus the search path. |
| Performance-only code generation changes | Main search prefetches a full-depth child's hash entry right after making the move. Single-square masks (`bit2nmask`, `bit2nmasknot`, `bit8mask`) are computed with shifts in hot code, and king squares use one bit scan because a king board holds exactly one bit; bounds-checked builds still validate those indexes and king boards. Move generators count in a local variable and publish the count on return. MSVC Release builds omit stack-cookie checks (`/GS-`). Evaluation, move order, node counts, scores, and PVs are unchanged. |
| WinBoard search lifecycle, period clocks, and game results | Routine clock/status commands leave search running; position changes and `force` discard its result. Move counts wrap for each time-control period. The adapter claims actual-game draws independently of the core's heuristic draw evaluation. |
| Transactional hash resizing and position input | Allocation or input failure preserves the previous usable table or position. Diagnostic FEN output includes all six fields. |
| Portable book/PGN file operations and paths | Removes form and Windows-path dependencies; book bytes and learning logic are unchanged. Missing files/paths are reported by the console where appropriate. |
| Omit GUI-only diagnostics and `TStringList` startup/finalization | Removes desktop captions and the original `C:\anu.txt` write. The translated diagnostic routines remain available but inactive. |

The console reconstructs repetition entries with the original **0/1 side indices**; search uses the same `2-giliran` convention. A new game does not pre-insert its initial position, matching the original GUI initialization.

The time allocator uses the supplied moves-to-go count, or a 30-move horizon for sudden death. It banks future response overhead up to half the current clock, then targets the remaining distributable clock divided by the horizon plus 80% of the increment. The hard search budget is at most three times the target and never exceeds the current clock minus overhead; future increment is not available until after the move. Fixed `movetime` is also reduced by overhead. Iterative deepening estimates the next iteration at twice the previous duration. These initial policy constants require tournament testing; no Elo gain is asserted. `original_time_budget()` and the translated quarter-second fields remain for provenance, but the console uses `TimeManager` for enforcement.

## Original limitations intentionally retained

These are future improvement candidates, not changes made in this version:

- The generator searches queen and knight promotions only. The maker can accept bishop/rook promotions from an opponent, as the original did. Standard perft positions that require all four generated promotions can therefore differ from published chess totals.
- The TT's 16-bit move field can truncate the rook-promotion encoding, which needs bit 16. The field was not widened in this faithful version.
- Repetition-table deletion still uses the original open-addressing behavior without tombstones.
- Mate scores retain their original TT encoding and root conventions; no ply normalization was added.
- The original `IsValid` pawn-file behavior, SEE treatment of pins/kings, and other check-evasion/search-pruning quirks are retained. En passant evasion legality and quiescence stalemate handling are corrected as listed above.
- Book candidates remain limited to 20 entries. Optional bounds checks detect exceeding that capacity. Move lists now have 256 entries and an unconditional capacity check.
- MTD(f) retains its original byte-sized depth parameter and is off by default.
- Node counters remain 32-bit, and the halfmove counter remains an 8-bit field.
- The legacy PGN learner is not a general PGN parser.

Because the Delphi application could not be compiled/run here, this is **not a claim of proven bit-for-bit search parity** against a running Delphi build. The original source, translation tooling, structural review, book-key compatibility, perft results, board-state invariants, and functional tests are provided to make that comparison practical.
